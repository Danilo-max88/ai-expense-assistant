# AI Expense Assistant

A REST API for tracking expenses that uses Claude to do two things a plain CRUD app can't: turn a free-form sentence into a structured expense record, and turn a pile of expense rows into a short, useful spending insight.

## Why this exists

Most "AI-powered" CRUD demos just forward a prompt to an LLM and print whatever comes back. That's unreliable for anything downstream — you can't insert "whatever the model felt like saying" into a database column. This project uses Claude's **tool use** feature to force the model into a fixed JSON schema when extracting structured data, so the output is guaranteed to parse, while reserving plain free-text generation for the one feature that's actually supposed to produce prose (the spending summary).

## Features

- `POST /expenses` — create an expense manually
- `POST /expenses/parse` — send a sentence like *"spent 1500 on groceries yesterday"* and get back a structured, saved expense (amount / category / description / date), extracted by Claude
- `GET /expenses` — list expenses, optionally filtered by category or date range
- `DELETE /expenses/{id}` — remove an expense
- `GET /expenses/summary?period=week|month` — totals by category plus a short natural-language insight generated by Claude

## Architecture

```
app/
├── main.py            FastAPI routes
├── database.py         SQLAlchemy engine/session
├── models.py           ORM model (Expense)
├── schemas.py          Pydantic request/response schemas
├── crud.py             Database operations
└── claude_service.py   All Claude API calls, isolated here
```

Claude calls are isolated in one module (`claude_service.py`) so the rest of the app never touches the Anthropic SDK directly — this is also what makes the test suite fast and free: tests mock `claude_service.get_client()` instead of hitting the real API, so `pytest` runs in well under a second with zero API cost and no API key required in CI.

### How the extraction actually works

`parse_expense_text()` doesn't ask Claude to "return JSON" and hope for the best. It defines a tool (`record_expense`) with a strict input schema and forces Claude to call it via `tool_choice={"type": "tool", "name": "record_expense"}`. The model's structured tool input *is* the parsed data — no string parsing, no "sometimes the model wraps it in a code block" bugs.

## Setup

```bash
git clone <this-repo>
cd ai-expense-assistant
python -m venv .venv
.venv\Scripts\Activate.ps1      # Windows PowerShell
pip install -r requirements.txt
cp .env.example .env            # then fill in ANTHROPIC_API_KEY
```

Run the API:

```bash
uvicorn app.main:app --reload
```

Interactive docs at `http://127.0.0.1:8000/docs`.

## Example usage

```bash
curl -X POST http://127.0.0.1:8000/expenses/parse \
  -H "Content-Type: application/json" \
  -d '{"text": "spent 1500 on groceries yesterday"}'

curl http://127.0.0.1:8000/expenses/summary?period=week
```

## Testing

```bash
pytest -v
```

No API key needed to run the test suite — Claude calls are mocked.

## Docker

```bash
docker build -t ai-expense-assistant .
docker run -p 8000:8000 --env-file .env ai-expense-assistant
```

## CI

GitHub Actions (`.github/workflows/ci.yml`) runs the full test suite on every push and pull request against `main`.

## Model choice

Defaults to `claude-opus-4-8`. For this kind of workload (short extraction + short summary), `claude-haiku-4-5` is noticeably cheaper and still accurate enough for everyday use — swap it via `ANTHROPIC_MODEL` in `.env` if you're running this a lot during development.
